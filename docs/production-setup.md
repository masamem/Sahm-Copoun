# تفعيل قاعدة بيانات كوبونيا ولوحة الإدارة

هذه المرحلة تجهز إدارة المتاجر والكوبونات. تحتاج إلى مشروع Supabase لتفعيل الحفظ الفعلي. لا تتضمن حسابات زوار أو إرسال بريد أو عروض مباشرة بدون كود.

1. أنشئ مشروعاً على https://supabase.com/dashboard أو استخدم مشروعاً تملكه.
2. شغّل `database/schema.sql` مرة واحدة في SQL Editor. ينشئ الجداول وصلاحيات الصفوف (RLS)، ولا يضيف بيانات تجريبية.
3. أنشئ مستخدم الإدارة من Authentication → Users، ثم انسخ معرّف UUID لهذا المستخدم.
4. من SQL Editor، عيّن حسابك مديراً باستخدام الأمر التالي مع استبدال UUID:

```sql
insert into public.admin_users(user_id) values ('YOUR_AUTH_USER_UUID');
```

لا تنفّذ هذه الخطوة لحساب آخر إلا إذا أردت منحه صلاحية إدارة جميع المتاجر والكوبونات. المستخدمون المسجلون الآخرون لا يملكون صلاحية تعديل البيانات.

5. في إعدادات مشروع Vercel `sahm` أضف:
   - `VITE_SUPABASE_URL`: عنوان المشروع.
   - `VITE_SUPABASE_PUBLISHABLE_KEY`: مفتاح **publishable** العام، وليس `service_role` أو مفتاحاً سرياً.
6. أعد نشر المشروع؛ متغيرات Vite تُقرأ وقت البناء.
7. افتح `/admin` وسجل الدخول بالحساب الذي عيّنته. أضف متجراً ورابطه HTTPS، ثم كوبوناً وشروطه وتاريخ انتهائه. فعّل ظهور المتجر ونشر الكوبون عند الجاهزية.

## التحقق قبل تفعيل الإنتاج

اختبر في مشروع Supabase تجريبي أولاً:
- الزائر يرى المتاجر النشطة والكوبونات المنشورة غير المنتهية فقط.
- مستخدم مسجل غير مدير لا يستطيع إنشاء متجر أو تعديل كوبون، حتى عبر REST مباشرة.
- الزائر لا يرى جدول `admin_users`؛ المدير يرى عضويته فقط ولا يستطيع إضافة مديرين عبر واجهة الموقع.
- المدير يستطيع حفظ مسودة ونشرها وإخفاء متجر. الكوبونات المنتهية تُخفى وفق تاريخ الرياض.
- انقطاع الاتصال يعرض خطأ وإعادة المحاولة، ولا يستبدل البيانات الحقيقية بأمثلة.
- شروط الكوبون ورابط المتجر وتاريخ انتهائه ظاهرة في التفاصيل.

## الجلسات والحدود الحالية

تسجيل الدخول عبر Supabase Auth. رمز الوصول محفوظ في ذاكرة الصفحة فقط، ولا تُحفظ كلمات المرور أو الرموز في التخزين المحلي. انتهاء الجلسة يتطلب تسجيل دخول جديد؛ إعادة تحميل لوحة الإدارة كذلك. صلاحيات الكتابة تُفرض في قاعدة البيانات، وليست مجرد إخفاء أزرار في الواجهة.

قبل إضافة متغيرات الربط يبقى الموقع في الوضع التجريبي. بعدها يبدأ الكتالوج الحقيقي فارغاً حتى يضيف المدير المحتوى. العروض المباشرة تبقى فارغة؛ التواصل والبريد والنطاق وسياسات المشغل النهائية مراحل لاحقة. نصوص الخصوصية الحالية تحتاج مراجعة بيانات المشغل والخدمات عند الإطلاق.
